2. Exact conversion used by the current training/evaluation code
---------------------------------------------------------------

Input field order in gt.txt:
  frame, object_id, a_idx, r_idx, a_width, r_width,
  e_idx, e_width, yaw_degree, class

Current model axes:
  range step     = 118.037109375 / (256 - 1) = 0.462890625 m/bin
  azimuth step   = 1 degree/bin
  elevation step = 1 degree/bin

For each Polar GT box, current code computes:
  radius      = r_idx * 0.462890625
  elevation   = -18 degrees + e_idx * 1 degree
  horizontal_range = radius * cos(elevation)
  decoded_L   = abs(r_width) * 0.462890625
  decoded_W   = horizontal_range * radians(abs(a_width) * 1 degree)
  decoded_BEV_area = decoded_L * decoded_W

Important:
  decoded_BEV_area is the Cartesian metric box area seen by the current model.
  It is NOT the location-independent physical footprint of the Sedan. Polar
  min/max extents mix vehicle length/width with range and viewing direction.

Independent Polar-file origin check:
  The official v2.1 labels store half_length, half_width and half_height, and
  the official K-Radar parser converts them to full dimensions by multiplying
  each by 2. However, replaying the Polar-v2 generation reproduces the saved
  Polar rows only when those half-dimensions are passed directly as if they
  were full dimensions. The replay uses the 8 box corners, lidar-to-radar
  translation (-2.54, +0.30, +0.70)m, Polar min/max bounds, range step
  0.484375m/bin, and 1-degree azimuth/elevation steps.

  Exact replay counts:
    Seq9:  2447/2448 (one source-version mismatch at frame 115 / ID18)
    Seq10: 3198/3198
    Seq11: 5455/5456 (one source-version/class mismatch at frame 229 / ID136)
    Seq12: 2976/2976
    Seq50: 1077/1077
    Seq51: 353/353
    Seq52: 438/438
    Seq53: 590/590

  Therefore the Polar-v2 files have a likely factor-of-two dimension issue
  relative to the official full physical boxes. This does not imply that the
  final decoded area is exactly one quarter, because a Polar min/max box is a
  nonlinear, viewpoint-dependent representation.

  There is also an axis mismatch: the Polar files were generated with
  0.484375m/bin, while the current model decodes with 0.462890625m/bin. The
  model step is 4.435% smaller; because decoded L and horizontal range both
  scale with this step, decoded area is 8.674% smaller than it would be with
  the Polar generator's range step.

4. How often does the decoded area change for the same object ID?
-----------------------------------------------------------------

Whole-ID variation is max(area)/min(area)-1 over all Sedan boxes carrying the
same object_id. Single-frame IDs are excluded. This can be large simply because
the vehicle moves relative to the radar.

Adjacent jump compares only consecutive annotated frames for one object ID and
is a better indicator of an abrupt discontinuity.

| Seq | Multi-frame Sedan IDs | IDs with whole-track decoded change >20% | Consecutive pairs | Pairs with jump >20% | Pairs with jump >50% |
|----:|----------------------:|-----------------------------------------:|------------------:|---------------------:|---------------------:|
| 9  | 18 | 11 (61.1%) | 1834 | 5 (0.273%)  | 1 (0.055%) |
| 10 | 15 | 12 (80.0%) | 2327 | 5 (0.215%)  | 2 (0.086%) |
| 11 | 41 | 32 (78.0%) | 3637 | 22 (0.605%) | 3 (0.082%) |
| 12 | 22 | 15 (68.2%) | 1951 | 8 (0.410%)  | 4 (0.205%) |
| 50 | 4  | 3 (75.0%)  | 1031 | 0 (0.000%)  | 0 (0.000%) |
| 51 | 3  | 3 (100.0%) | 247  | 1 (0.405%)  | 0 (0.000%) |
| 52 | 2  | 2 (100.0%) | 396  | 0 (0.000%)  | 0 (0.000%) |
| 53 | 2  | 1 (50.0%)  | 584  | 0 (0.000%)  | 0 (0.000%) |

Interpretation:
  Large whole-track decoded changes are common, but abrupt adjacent-frame jumps
  are rare. Across Seq9-12, only 40/9749 = 0.410% of consecutive pairs jump by
  more than 20%. Across Seq50-53, only 1/2258 = 0.044% does.

Key controls:
  - Seq9: of 18 multi-frame IDs, 14 have exactly constant strict L*W, two
    change by 5-20%, and only ID1 and ID76 change by more than 20%.
  - Seq50: all four IDs have exactly constant strict L*W, even though 3/4 IDs
    have more than 20% whole-track variation in the model-decoded area.

This proves that a large Polar-decoded area variation often comes from the
coordinate representation and target viewpoint, while a smaller subset is a
real change in the official annotation dimensions.

6. Seq9 object ID 1 audit
-------------------------

Current Polar GT decoded by the exact model function:
  frame 219: center=(12.0893,-3.1372)m, L=2.8831m, W=1.5397m,
             area=4.4391m^2
  frame 220: center=(12.1968,-3.1633)m, L=3.2335m, W=1.9514m,
             area=6.3099m^2

The center moves only about 0.111m and yaw remains -0.1798 degrees, while the
decoded area jumps by 42.1%. This is a genuine abrupt change in the annotations
carrying the same ID; it is not an ID grouping artifact.

The previously reported 10.634 -> 16.281m^2 values refer to the official source
Cartesian annotation, not the current Polar-to-Cartesian model decoding:
  frame 219 strict source: L=5.6439m, W=1.8842m, area=10.6344m^2
  frame 220 strict source: L=6.1576m, W=2.6440m, area=16.2807m^2

Therefore both changes exist, but they belong to two different area definitions.
